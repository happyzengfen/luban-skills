# 任务卡：通勤路上通过飞书指挥 OpenClaw 的 6 张连贯漫画（稳态版）

## 任务类型
多图连贯漫画正式交付任务

## 任务主题
生成一组 6 张连贯漫画，描述一位上班族在通勤路上通过飞书指挥 OpenClaw 完成工作事项。

## 输出目录
`<workspace>/outputs/commute-feishu-openclaw-comic/`

## 主交付目标（必须达成）
1. 产出 6 张实际图片文件到输出目录
2. 6 张图角色一致、服装一致、画风一致、手机 UI 风格一致
3. 6 张图剧情连续，时间线固定为：家门口 → 地铁站台 → 地铁车厢 → 接驳公交/步行段 → 写字楼门口 → 办公室工位
4. 每张图可以单独重生成，不依赖整批一次成功
5. 只有 6 张图片全部成功落盘，才算正式完成

## 允许的降级路径（仅在后端异常时）
如果图片后端异常，允许降级输出以下内容：
- 统一角色设定
- 统一画风规范
- 6 格连续剧情
- 每张图最终中文提示词
- 已成功落盘的部分图片（若有）

但必须明确标记交付状态：
- 正式版：6/6 图片全部落盘
- 预览版：部分图片成功落盘
- 方案版：仅有文字方案与提示词

⚠️ 只有预览版或方案版时，不得表述为“任务已正式完成”。

## 强制执行顺序

### Step 1 — 先锁统一设定
先产出并保存：
1. 主角角色 bible
   - 年龄、职业、性别
   - 发型、五官、肤色、眼镜
   - 固定服装
   - 固定道具
2. 统一画风规范
   - 线条风格
   - 色彩基调
   - 光线氛围
   - 镜头语言
3. UI 表现规则
   - 手机界面表现为抽象协作聊天 UI
   - 不得精确复刻真实品牌 logo
4. 6 格剧情骨架

### Step 2 — 先生成第 1 张探针图
先只生成第 1 张，并验证：
1. 图片后端是否真实可用
2. 是否成功返回图像数据
3. 是否真实落盘到输出目录
4. 风格是否符合角色与画风要求
5. 是否具备继续生成第 2-6 张的条件

如果第 1 张失败：
- 立即停止整批渲染
- 输出失败证据
- 将结果标记为“方案版”
- 不得声称任务完成

### Step 3 — 探针成功后逐张生成第 2-6 张
要求：
1. 每张图独立请求
2. 每张图独立超时
3. 每张图独立落盘
4. 每张图独立记录 success / error / 文件路径 / 文件大小
5. 任一单张失败，不得影响已成功图片保留

⚠️ 不允许把 6 张图绑定成一次长串行渲染，避免超时后 0 图落盘。

### Step 4 — 最终交付必须分级
最终必须输出：
1. 统一角色设定
2. 统一画风规范
3. 6 格剧情结构
4. 每张图最终中文提示词
5. 图片落盘结果清单
6. 最终交付状态（正式版 / 预览版 / 方案版）
7. 若失败，必须附阻断证据和最小恢复动作

## 角色设定（固定锚点）
- 主角：林舟，29 岁男性项目经理，上班族气质
- 外观：黑色短发微卷，细框眼镜，肤色偏白，表情灵活，略带困意但反应快
- 固定穿着：米白色风衣、雾蓝衬衫、深灰西裤、白色运动鞋、黑色斜挎包
- 固定道具：手机、无线耳机、咖啡杯、工牌
- OpenClaw 表现规则：只出现在手机聊天气泡、任务卡片、文件卡片、进度卡片、提醒卡片中，不拟人化

## 画风规范（固定锚点）
- 风格：现代都市轻喜剧漫画
- 形式：2D 干净线条，轻微赛璐璐上色
- 色彩：奶油黄、地铁灰蓝、晨光橙、办公室木色
- 氛围：温暖晨光、轻快节奏、都市通勤感
- 连续性：6 张图必须保持同一角色长相、服装、手机 UI 样式一致
- 品牌规则：不得精确复制真实品牌 logo，仅表现抽象协作聊天界面

## 6 格剧情骨架
1. 家门口：林舟出门时通过飞书给 OpenClaw 发消息，先整理今日日报重点
2. 地铁站台：查看 OpenClaw 整理的关键任务卡片
3. 地铁车厢：让 OpenClaw 先生成评审会资料初稿
4. 接驳公交/步行段：同步项目进度并标出风险点
5. 写字楼门口：收到会议提醒并让 OpenClaw 把材料发到群聊
6. 办公室工位：到岗时手机显示事项已完成，故事闭环

## Prompt 编写强制规则
每张图最终提示词都必须包含：
1. 全局角色锚点
2. 全局画风锚点
3. 当前场景描述
4. 当前动作与情绪
5. 当前对白或屏幕文字
6. 连续性约束（与上一张保持一致）
7. 禁止项（不得出现真实品牌 logo）

## 文件要求
至少应产出以下文件：
- `storyboard.md` 或等价分镜文档
- `render-results.json`
- `frame-01.png` 至 `frame-06.png`（正式版）
- 若为部分成功，至少保留已生成图片与对应结果记录

## 验收标准
### 正式版
- 6/6 图片全部存在
- 文件可打开
- 角色与画风连续一致
- 剧情完整闭环

### 预览版
- 至少有 1 张图片成功落盘
- 已记录失败图片编号与原因
- 附完整 storyboard 与 prompt

### 方案版
- 没有任何图片成功落盘
- 但已输出完整设定、剧情、提示词和失败证据
- 明确标注为未正式完成

## 推荐一句话执行原则
先证明“能生成并落盘”，再扩展到 6 张；不要先把文本做满，再把图片生成当附带尝试。
