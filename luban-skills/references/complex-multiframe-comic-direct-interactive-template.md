# 复杂多图漫画任务场景模板（直接交互版优先）

## 适用场景
- 6格/多格连贯漫画
- 系列插画 / 连续海报
- 要求角色一致、剧情连续、后续还能继续改单张的任务

## 不要这样下任务
不要把目标写成：
- 先出分镜和提示词
- 如能生图就顺手生成
- 失败就退化为“有方案也算完成”

这种写法会导致：
1. ACP/Hermes 把文本方案视为主交付
2. 图片生成只成为“附带尝试”
3. 一旦后端超时，就自然收尾成 partial
4. 最终任务目标从“可交互成图”退化为“有 storyboard 就算完成”

## 推荐任务目标定义
### 主目标（必须）
Hermes 直接完成 **可交互版本**：
- 产出 6 张实际图片文件
- 角色一致
- 画风一致
- 剧情连续
- 每张图支持后续单独重生成 / 修改

### 次目标（仅兜底）
如果后端异常，才退化为：
- 完整分镜
- 统一角色设定
- 统一画风设定
- 每张图最终提示词
- 明确标记为“预览版/兜底版”，不算正式闭环

## 推荐任务卡写法
```markdown
目标：生成 6 张连贯漫画，描述一个上班族在通勤路上通过飞书指挥 OpenClaw 完成任务。

成功标准：
1. 必须产出 6 张实际图片文件到指定目录
2. 6 张图角色一致、服装一致、手机UI风格一致
3. 6 张图剧情连续，时间线从家门口 → 地铁站台 → 地铁车厢 → 接驳公交/步行 → 写字楼门口 → 办公室工位
4. 每张图都能单独重生成，不依赖一次性整批成功
5. 若图片后端失败，只能降级为“预览方案版”，不得表述为正式完成
```

## 推荐执行顺序
### Step 1 — 先做单图探针，不要一上来 6 连发
先生成 **第1张** 作为探针图，验证：
- image_generate 后端是否可用
- 单图能否在限定时间内完成
- 返回是否能落盘

只有探针成功，才进入 6 图批量阶段。

### Step 2 — 每张图独立生成、独立落盘
不要把 6 张图绑成一次长脚本串行调用后再统一收尾。

推荐：
- 每张图单独请求
- 每张图单独超时
- 每张图单独记录结果
- 允许 `frame-01.png` 成功而 `frame-04.png` 失败

这样至少不会出现“600秒后 0 文件”的最差结果。

### Step 3 — 先锁角色 bible，再生成每一格
固定：
- 主角外观
- 服装
- 道具
- 手机界面样式
- 色彩基调
- 镜头语言

并把这些内容作为每一格 prompt 的前缀常量，而不是仅在 storyboard 文档里描述一次。

### Step 4 — 交付分级必须写死
#### 正式版
- 6 张图片全落盘
- 支持继续改单张

#### 预览版
- 有部分图或只有探针图
- 可确认风格方向

#### 方案版
- 只有 storyboard / prompt / 角色设定
- 不算成图完成

## 推荐 prompt 结构
每张图都拆成：
1. 全局角色锚点
2. 全局画风锚点
3. 当前分镜场景
4. 当前对白/屏幕文字
5. 连续性约束（与上一张保持一致）
6. 禁止项（不要真实品牌logo等）

## 本次日志暴露出的典型问题
### 问题1：成功标准偏向文本，不偏向成图
日志中已写：
- “优先交付 6 条可直接用于 image_generate 的最终中文提示词”
- “如具备图片工具链，则尝试生成实际图片文件”

这会把图片生成降为“尽量做”，不是“必须达成”。

### 问题2：先写完整 6 格脚本，再一次性渲染
导致：
- 第1张就超时
- 整批 600s 卡死
- 最终 0 图落盘

### 问题3：反思逻辑过早接受 partial
日志中的反思已经把“完整分镜+提示词”视为主交付，这对复杂多图任务不够严格。

## 更优场景文案（可直接复用）
```markdown
使用 luban-skills 完成一个 6 张连贯漫画任务，主题为：上班族通勤路上通过飞书指挥 OpenClaw 完成工作事项。

要求：
1. 先定义统一角色 bible（发型、服装、道具、手机UI、色彩风格）
2. 先生成第1张探针图并落盘，验证生图链路真实可用
3. 探针成功后，再逐张生成第2-6张
4. 每张图必须独立保存，允许部分成功，不允许因为整批超时导致0图
5. 每张图都必须支持后续单独重生成和重写 prompt
6. 若后端失败，必须明确标记为“方案版/预览版”，不能表述为任务正式完成
```

## 一句话原则
**复杂多图任务的默认目标，应是“先打通可交互成图链路”，不是“先把 storyboard 写漂亮”。**
