# 四类常见任务交付模板

本文件给出 4 类典型任务的**交付结构**和**验收要求**。OpenClaw 接到需求后，先按类型套模板，再根据具体上下文填内容。

---

## 模板 1 — 写作类

适用：邮件 / 汇报稿 / 方案 / 总结 / 通知 / 文案

### 处理流程
1. 提炼目标读者
2. 明确用途（对内/对外，汇报/说服/通知）
3. 提炼要点（回读给用户确认）
4. 先出结构（不先写正文）
5. 再补正文
6. 最后做语气与格式优化

### 交付物结构
```
【标题/主题】
【称呼】（邮件类）
【正文】
  - 段 1：背景 / 起因
  - 段 2：重点结论 / 建议
  - 段 3：下一步 / 待确认项（可选）
【落款】（邮件类）
```

### 验收要求
- [ ] 可直接复制使用
- [ ] 语言风格符合场景（正式 / 半正式 / 轻松）
- [ ] 结构清晰、层次分明
- [ ] 不空泛，每句话都有信息量
- [ ] 不超过用户指定的长度

---

## 模板 2 — 整理类

适用：多份文档 / 会议记录 / 零散笔记 / 上传文件

### 处理流程
1. 先分类（按主题 / 按时间 / 按来源）
2. 提取重复信息（共识）和关键差异（分歧）
3. 提炼结论
4. 输出结构化整理结果
5. 明确后续行动项

### 交付物结构
```markdown
# 主题

## 背景
（3 行内说明为什么要整理这些）

## 共识结论
1. 结论一（来源：A.md, B.md）
2. 结论二（来源：B.md, C.md）

## 分歧点
| 议题 | 观点 A | 观点 B |
|------|--------|--------|
| ... | ... | ... |

## 待办事项
- [ ] 行动 1（负责人 / 期限）
- [ ] 行动 2

## 附：原文引用
（可选）
```

### 验收要求
- [ ] 不是摘抄，是归纳
- [ ] 有重点，不是流水账
- [ ] 每条结论标注来源
- [ ] 共识与分歧分开
- [ ] 有可执行的行动项

---

## 模板 3 — 分析类

适用：表格 / 方案对比 / 风险排查 / 异常现象 / 现状与改进建议

### 处理流程
1. 先界定问题（问题边界、范围）
2. 先看事实和数据（不先解读）
3. 再做归因
4. 形成建议
5. 给出优先级

### 交付物结构
```markdown
# 分析：XXX

## 1. 问题界定
- 问题是什么
- 影响范围
- 不讨论的部分

## 2. 事实与数据
- 数据点 1（来源）
- 数据点 2（来源）
- 观察到的现象

## 3. 归因分析
- 原因 1（证据）
- 原因 2（证据）
- 未知 / 待验证的部分

## 4. 建议
| # | 建议 | 优先级 | 成本 | 预期效果 |
|---|------|--------|------|----------|
| 1 | ... | 高 | 低 | ... |
| 2 | ... | 中 | 中 | ... |

## 5. 下一步
- 立即要做的
- 需要用户决策的
```

### 验收要求
- [ ] 结论有依据（每个结论能追溯到数据）
- [ ] 建议具体（不是"加强管理"这种空话）
- [ ] 能落地（明确谁、何时、做什么）
- [ ] 能说明为什么（归因清晰）
- [ ] 区分"已验证 / 推测 / 未知"

## 模板 4 — 规划类

适用：项目计划 / 多步骤工作 / 长周期任务 / 跨人协同任务

### 处理流程
1. 明确终点（验收标准）
2. 拆里程碑
3. 标出依赖关系
4. 标出需要确认的节点
5. 先做一个最小可行版本（MVP）

### 交付物结构
```markdown
# 计划：XXX

## 终点（验收标准）
- 什么情况下算"完成"

## 里程碑
| # | 里程碑 | 交付物 | 依赖 | 时间 |
|---|--------|--------|------|------|
| M1 | ... | ... | 无 | Week 1 |
| M2 | ... | ... | M1 | Week 2 |
| M3 | ... | ... | M2 | Week 3 |

## 关键路径
M1 → M2 → M3

## 需要确认的节点
- M1 结束时：确认方向是否正确
- M2 结束时：确认数据接入是否稳定

## MVP 最小可行版本
- 只包含 M1 的核心动作
- 1 天内可完成
- 用于验证假设

## 风险与备选方案
- 风险 1 → 备选 A
- 风险 2 → 备选 B
```

### 验收要求
- [ ] 步骤清楚，顺序合理
- [ ] 能实际推进（不是空中楼阁）
- [ ] 包含验收标准（每个里程碑都有）
- [ ] 标出关键路径
- [ ] 包含 MVP（最小可行版本）
- [ ] 标明需要人工确认的节点

---

## 通用原则

1. **交付物必须可以独立存在**。用户不需要配合 OpenClaw 的执行日志也能读懂。
2. **每个模板都包含"下一步"**。不要让用户读完不知道该做什么。
3. **表格优先**。复杂信息用表格比大段文字更容易对齐。
4. **可勾选列表**。待办类内容一律用 `- [ ]` 格式，方便用户直接打勾。
