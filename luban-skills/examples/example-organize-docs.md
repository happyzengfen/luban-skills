# 示例：整理 3 份产品调研资料

## 用户原话
> "我有 3 份产品调研资料，你帮我整理一下共同结论和分歧点，最后给我一份可以直接用的文档。"

---

## OpenClaw 内部任务卡

```yaml
任务名称: 整理 3 份产品调研资料的共识与分歧
任务类型: 整理类
最终交付物: 一份结构化 Markdown（共识 / 分歧 / 待办）
输入材料:
  - ./research/A.md
  - ./research/B.md
  - ./research/C.md
关键约束:
  - 不能抄原文，要归纳
  - 共识与分歧必须分开
  - 每条结论标注来源
  - 输出 Markdown 格式
风险点:
  - 把单一资料的观点当成共识
  - 遗漏反对意见
  - 被无关章节带偏
最小闭环动作: 先读 1 份（A），输出样例结构给用户确认
是否需要 Hermes: 是
是否需要人工确认:
  - 样例结构出来后
  - 全量整理完成后
验收标准:
  - 每条结论有出处
  - 共识与分歧分开
  - 包含待办清单
```

---

## OpenClaw 对用户说什么

> "3 份资料我一份一份读。我先读第一份，给你看看整理的样例结构对不对，你觉得结构 OK 我再批量处理剩下两份。这样能避免结构错了白做一遍。"

---

## Hermes 子任务 1（读 A.md，输出样例结构）

```
TASK:
  目标: 从 A.md 提取用于"共识/分歧"整理的样例结构
  输入: ./research/A.md
  可读目录: [./research/]
  验收标准:
    - 输出 Markdown 骨架（标题层级、表格列定义）
    - 不超过 200 字
    - 每个信息点附原文段落编号
```

---

## Hermes 回传（样例结构）

```markdown
# 产品调研整理

## 背景
（此处放 3 行概述）

## 共识结论
1. 结论文本（来源：A §X, B §Y）

## 分歧点
| 议题 | 观点 A | 观点 B | 观点 C |
|------|--------|--------|--------|
| ... | ... | ... | ... |

## 待办事项
- [ ] 行动 1（负责人 / 期限）

## 来源
- A.md: 摘录位置
- B.md: 摘录位置
- C.md: 摘录位置
```

---

## 用户确认结构后，Hermes 子任务 2（批量整理）

```
TASK:
  目标: 按上一步确认的结构，合并 A/B/C 三份资料
  输入: ./research/{A,B,C}.md
  可读目录: [./research/]
  验收标准:
    - 共识结论至少在 2 份资料中出现
    - 分歧点必须来自不同资料的矛盾表述
    - 所有结论标出处
  风险提示: 不要把 A 独有的观点列为共识
```

---

## 最终交付物

```markdown
# 产品调研整理（A / B / C）

## 背景
3 份独立调研均围绕 X 产品方向进行用户访谈与竞品分析。目的：汇总共识、找分歧、定下一步。

## 共识结论
1. **用户对核心功能 F1 需求强烈** — A §2.1, B §1.3, C §3.2
2. **付费意愿集中在 ¥20-30/月档位** — A §4.2, B §4.1
3. **竞品 X 的体验短板在 UI 跳转逻辑** — B §5.1, C §5.3

## 分歧点
| 议题 | 观点 A | 观点 B | 观点 C |
|------|--------|--------|--------|
| 目标人群 | 学生党为主 | 职场人士为主 | 学生 + 职场兼顾 |
| MVP 功能范围 | 只做 F1 | F1 + F2 | F1 + F3 |
| 上线节奏 | 2 周内 | 1 个月 | 6 周 |

## 待办事项
- [ ] 对齐目标人群定义（负责人：PM，本周五前）
- [ ] MVP 功能范围决议会议（负责人：Tech Lead，下周一前）
- [ ] 上线节奏估算（负责人：工程 + 设计，下周三前）

## 来源
- A.md — 学生群体调研（2026-04-10）
- B.md — 职场用户访谈（2026-04-15）
- C.md — 混合样本调研（2026-04-20）
```

---

## 验收检查

- [x] 不是摘抄，是归纳
- [x] 共识 / 分歧分开
- [x] 每条结论标出处
- [x] 有可执行的行动项（含负责人、期限）
- [x] 用户可直接复制使用

---

## 关键点总结

1. **先样例，再全量**。样例结构确认错了再重来成本极低；全量做完再改成本极高。
2. **共识的门槛要清晰**："至少 2 份资料出现" 是硬标准，避免单份观点误列。
3. **分歧点用表格**。多维对比用表格比文字清晰 10 倍。
4. **每条结论必标来源**。防止用户追问"这是哪儿说的？"时无从回答。
5. **待办清单 + 负责人 + 期限**。不带负责人和期限的待办等于没做。
