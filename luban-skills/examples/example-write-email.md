# 示例：写一封项目周会汇报邮件

## 用户原话
> "帮我根据这份会议纪要，给张总写一封项目周会邮件，200 字内，语气正式。"

---

## OpenClaw 内部任务卡

```yaml
任务名称: 给张总写项目周会邮件
任务类型: 写作类
最终交付物: 一封 200 字内、语气正式、可直接发送的邮件
输入材料:
  - ./会议纪要-2026-04-23.md
关键约束:
  - 不超过 200 字
  - 不超过 3 段
  - 正式语气
  - 不泄露未确认数字
风险点:
  - 误把草案数字当最终数字
  - 被纪要里的无关议题带偏
  - 对外发送后不可回退
最小闭环动作: 从纪要提炼 3 个要点并回读给用户确认
是否需要 Hermes: 是
是否需要人工确认:
  - 要点提炼完成后
  - 邮件初稿完成后
  - 最终发送前
验收标准: 用户可直接复制发送
```

---

## OpenClaw 对用户说什么

> "我先读一下这份纪要，提炼 3 个要点。等你确认要点无误，我再出一版简洁的邮件初稿给你看。最后你确认了，我再按正式邮件格式做最后调整。整个过程有三个确认点。"

（不要说"进入 Phase 1 Intent Parsing" 或 "启动 ACP 调度"）

---

## Hermes 子任务 prompt（OpenClaw 通过 ACP 下发）

```
ROLE: 你是 Hermes，在受控边界内执行子任务。
EXECUTION MODEL: Intent → ReAct → Reflect

TASK:
  任务名称: 从会议纪要提炼 3 个给张总的汇报要点
  输入材料: ./会议纪要-2026-04-23.md
  可读目录: [./]
  可写目录: []
  禁止: 读取 ./ 以外任何目录；引用历史纪要
  验收标准:
    - 恰好 3 个要点
    - 每个要点附原文章节编号
    - 总字数不超过 150
    - 不包含未确认数字
  风险提示: 纪要中含"草案"章节，需自动排除

开始执行。严格按 Intent → ReAct → Reflect 三阶段，最后按 OUTPUT SCHEMA 返回 JSON。
```

---

>

## 验收检查（OpenClaw 内部）

- [x] 完成目标：邮件写好了
- [x] 符合格式：有主题 / 称呼 / 正文 / 落款
- [x] 关键约束：≤200 字（148 字），3 段，语气正式
- [x] 无关键信息遗漏：3 个要点都在
- [x] 未越界：只读了指定纪要文件
- [x] 明确了确认点：最终发送前再次确认
- [x] 可直接复制使用：是

**✅ 满足全部 7 项成功标准。**

---

## 关键点总结

1. **三次确认**：要点确认 → 初稿确认 → 发送前确认，保证对外内容不翻车
2. **先读后写**：先把纪要读完并确认要点，再写邮件
3. **明确排除**：纪要里的"草案"章节通过 prompt 明确排除
4. **表达转换**：对用户始终说自然话，对 Hermes 用结构化 prompt
5. **可回退**：每一步都能回到上一个稳定点（要点、初稿）重来
