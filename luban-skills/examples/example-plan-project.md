# 示例：规划一个复杂项目

## 用户原话
> "我们要做一个新功能 X，涉及前端、后端、测试、上线。你帮我拆一下，先给我一个最小可行版本，别一步做到头。"

---

## OpenClaw 内部任务卡

```yaml
任务名称: 功能 X 实施规划
任务类型: 规划类
最终交付物: 里程碑 + 依赖 + MVP + 验收标准的完整推进计划
输入材料:
  - 用户口述的功能概述（3 句）
关键约束:
  - 必须先给 MVP
  - 明确依赖关系
  - 标出需要确认的节点
  - 不做到头（分阶段）
风险点:
  - 拆得太细陷入细节
  - MVP 过度设计
  - 忽略跨角色依赖
最小闭环动作: 先列 MVP（1 天可完成的最小版本），用户确认再扩展
是否需要 Hermes: 否（规划类任务 OpenClaw 可直接完成）
是否需要人工确认:
  - MVP 确认后再扩展到完整计划
验收标准:
  - 有 MVP
  - 有里程碑表
  - 标出关键路径
  - 含验收标准
  - 有备选方案
```

---

## OpenClaw 对用户说什么

> "我先给你一个 1 天能跑通的 MVP 版本，你看看方向对不对。方向确认了我再扩展到完整的多里程碑计划。这样避免一开始就把计划画得太满。"

---

## 第一轮输出 — MVP

```markdown
# 功能 X — MVP（v0.1）

## 目标
1 天内跑通最小闭环：用户 A 触发功能 X → 后端返回结果 → 前端展示。

## 范围
**做**：
- 1 个后端接口（POST /api/x，写死 mock 返回）
- 1 个前端按钮 + 结果展示区
- 1 条 happy path 测试用例

**不做**：
- 任何错误处理
- 任何权限校验
- 任何数据持久化
- 任何 UI 美化

## 验收
- [ ] 在 dev 环境点按钮能看到 mock 结果
- [ ] 后端接口返回 200
- [ ] 测试用例绿

## 预期耗时
- 后端 mock 接口: 1 小时
- 前端按钮 + 展示: 2 小时
- 联调 + 测试: 1 小时
- 合计: 半天 ~ 1 天
```

---

## 用户确认 MVP 方向后，扩展完整计划

```markdown
# 功能 X — 完整推进计划

## 终点（验收标准）
- 功能 X 在生产环境对指定用户群灰度开放
- 错误率 < 0.1%
- p95 延迟 < 300ms
- 有可回滚开关

## 里程碑
| # | 里程碑 | 交付物 | 依赖 | 预计时间 |
|---|--------|--------|------|---------|
| M0 | MVP | dev 环境跑通 mock 闭环 | 无 | 1 天 |
| M1 | 后端正式实现 | 真实业务逻辑 + 单测 | M0 | 3 天 |
| M2 | 前端完整 UI | 完整交互 + 错误态 | M0 | 3 天（可与 M1 并行） |
| M3 | 数据持久化 | DB schema + 迁移脚本 | M1 | 2 天 |
| M4 | 权限 + 灰度开关 | 权限检查 + feature flag | M1, M2 | 1 天 |
| M5 | 集成测试 + 压测 | E2E 用例 + 压测报告 | M1, M2, M3 | 2 天 |
| M6 | 灰度上线 | 生产环境 5% 流量 | M4, M5 | 1 天 |
| M7 | 全量 | 100% 流量 + 监控接入 | M6（+ 观察 3 天无异常） | 1 天 |

## 关键路径
M0 → M1 → M3 → M5 → M6 → M7

（M2 与 M1 可并行；M4 不在关键路径）

## 需要确认的节点
- **M0 结束时** — 确认方向对不对（防止返工）
- **M1 结束时** — 确认后端行为符合预期
- **M5 结束时** — 压测结果是否达标
- **M6 之前** — 生产上线最终确认
- **M7 之前** — 灰度观察期有无异常

## MVP（同上）
见"第一轮输出"。

## 风险与备选
| 风险 | 影响 | 备选 |
|------|------|------|
| 第三方依赖延期 | M1 受阻 | M1 先用 mock，M3 接入真实依赖 |
| 压测不达标 | M6 延期 | 先缩小灰度范围（1%），优化后再扩 |
| 前端资源紧张 | M2 延期 | 简化 UI，降级到 MVP+ |

## 角色分工（待用户补充）
- 后端: ?
- 前端: ?
- 测试: ?
- PM: ?
```

---

## 验收检查

- [x] 步骤清楚，顺序合理
- [x] 能实际推进
- [x] 包含验收标准（每个里程碑都有隐含验收）
- [x] 标出关键路径
- [x] 包含 MVP
- [x] 标明需要人工确认的节点（5 个）
- [x] 有备选方案

---

## 关键点总结

1. **先 MVP，后全量**。不要上来就给 7 个里程碑；先给 1 天能验证的 MVP。
2. **关键路径 vs 非关键路径**。M2 与 M1 并行是省时间的关键。
3. **确认节点要具体**。"M0 结束时"比"阶段性确认"明确 10 倍。
4. **备选方案要有具体降级路径**。"受阻了"不是备选，"先用 mock"才是。
5. **角色分工留空让用户填**。你不知道他们团队谁做什么，留白比瞎填好。
6. **不要把计划画满**。留备选、留确认点、留观察期。
